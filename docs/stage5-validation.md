# Этап 5: реализация и предстоящая проверка

## Реализовано

- Приложение запускается со стартового экрана. Он показывает черновики и историю открытых документов отдельно; открытие и создание документа выполняются там. Существующие черновики этапа 4 читаются без переноса формата.
- Настройки автосохранения, языка проверки, раскладки будущих Vim-команд и вида по умолчанию находятся на стартовом экране. Выбранная задержка используется фоновой записью новых окон редактора.
- На Windows каждый документ открывается в своём окне. Повторное открытие того же ID переводит к имеющемуся окну. При закрытии последнего окна документа стартовое окно показывается снова.
- На Android для окон документов добавлена отдельная `DocumentActivity` с режимом документных задач. Нативный переход через `ActivityManager.AppTask` нужен потому, что `setFocus()` в используемой Android-реализации Tauri не реализован. Кнопка «Назад» сохраняет документ и возвращает к стартовому экрану. На устройствах без поддержки нескольких окон приложение переходит к документу внутри текущего окна.
- Черновик сохраняет ID, место сохранения, вид, выделение и прокрутку каждого документа. Для каждого окна создаётся собственная очередь фонового сохранения.

## Проверено сборкой

- `npm run build` и Windows `tauri build --debug --no-bundle` прошли.
- Android `tauri android build --debug --target x86_64` и `--target aarch64` прошли, включая компиляцию Kotlin и нативного перехода между задачами.
- Готовые файлы для проверки лежат в игнорируемом Git каталоге `builds/`: `DOCX-Vim-0.1.0-stage5-windows-debug.exe` и `DOCX-Vim-0.1.0-stage5-android-debug.apk`.

## Проверить позже на устройствах

1. На Windows открыть два разных DOCX, править и сохранять каждый независимо, повторно выбрать один из них и проверить переход к его окну.
2. Закрыть окна документов по очереди, затем приложение; проверить черновики, историю и возврат к стартовому экрану.
3. На Android открыть два DOCX, проверить отдельные карточки в системном списке недавних приложений, их названия и переход кнопкой «Документы».
4. После выгрузки процесса и повторного запуска проверить восстановление каждого черновика, выбранного файла, вида и курсора; на телефоне также проверить доступ к URI документ-провайдера.
5. На Android ниже API 32 проверить переход к документу внутри приложения вместо отдельного окна.

Оконные команды Vim, включая `Ctrl-W s/v`, `:split` и переходы между окнами, будут подключены вместе с движком Vim на этапе 6. Для второго окна того же документа потребуется одна общая модель изменений и единственная очередь записи DOCX, чтобы окна не перезаписывали правки друг друга.
