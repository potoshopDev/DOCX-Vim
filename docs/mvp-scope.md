# Объём первой версии DOCX-редактора

Статус: рабочее решение для этапа 1. Дата: 23.10.2026.

## Цель первой версии

Пользователь открывает обычный `.docx` на Windows или Android, редактирует текст и базовое форматирование в виде страницы либо в мобильном виде, управляет документом основными командами Vim, видит орфографические ошибки и сохраняет результат в `.docx`. Локальная работа и автосохранение доступны без учётной записи и сети. Пользователь может выбрать сохранение в OneDrive или Яндекс Диск на обеих платформах; грамматическая проверка может потребовать отдельно настроенного сервиса.

## Поддерживаемое содержание DOCX

| Элемент | Требование первой версии |
| --- | --- |
| Абзацы, пустые строки, ручной перевод строки | Открывать, редактировать, сохранять. |
| Заголовки 1–3 и обычный текст | Сохранять семантический стиль. |
| Жирный, курсив, подчёркивание, зачёркивание | Открывать, изменять, сохранять. |
| Маркированные и нумерованные списки | Поддерживать один уровень вложенности в MVP; более глубокие уровни выявлять при импорте. |
| Выравнивание абзаца, ссылки | Открывать, изменять, сохранять. |
| Простые таблицы | Открывать и менять текст ячеек; проверять сохранение строк и столбцов. Объединённые ячейки пока не гарантируются. |
| Изображения | Показать встроенные изображения и сохранить их; позиционирование — в строке документа. |
| Разрывы страниц | Распознавать и сохранять явные разрывы, если конвертер это позволит; проверить прототипом до обещания поддержки. |

Сложная вёрстка Word (плавающие объекты, текстовые поля, разделы, колонтитулы, сноски, комментарии, отслеживание изменений, формы, макросы) **не входит в гарантированный круговой обмен MVP**. Ограничения перечислены в документации приложения. Импортированный DOCX по умолчанию сохраняется через «Сохранить как», без автоматической перезаписи исходника; сообщения об ошибках и предупреждения в интерфейсе не выводятся.

## Языки и проверка ошибок

- Языки первой версии: **русский и английский**. Язык выбирается для документа; автоматическое определение смешанного текста — позже.
- Орфография: подчёркивание ошибок и список вариантов замены; применять замену без снятия форматирования соседнего текста.
- Грамматика: интерфейс замечаний и исправлений входит в архитектуру, но качество и доступность зависят от подключённого LanguageTool или другого сервиса. Публичный API LanguageTool не использовать для автоматической проверки приложения.
- Проверка отключается пользователем. Текст не отправляется в сеть без явного включения сетевой проверки.

### Кириллица и Unicode: обязательное условие до основного редактора

Проверены шесть файлов из `e/`: `word/document.xml` в каждом объявлен как UTF-8, XML читается без ошибки, русские буквы извлекаются, символа замены `�` в тексте нет. У трёх файлов при этом внутри встречается метка `en-US` на русском содержимом. **Не определять язык проверки только по метке DOCX**: при открытии дать выбор `ru-RU` / `en-US`, по умолчанию для этих образцов использовать русский.

Риск проекта — не «перекодировка DOCX в CP1251», а потеря Unicode при преобразовании DOCX → HTML → модель редактора → DOCX и неверное смещение курсора. XML читать библиотекой с учётом его объявления кодировки; не декодировать байты DOCX как текст целиком и не применять CP1251. Сохранять обычный Unicode-текст; сравнивать импорт и экспорт по нормализованным текстовым фрагментам, не нормализуя исходник молча.

Перед реализацией Vim-команд и проверки ошибок сделать сквозной тест на кириллицу: `Ё/ё`, смешанный русский/английский, кавычки `«»`, длинное тире, неразрывный пробел, комбинируемые знаки и emoji. Для пользовательских движений считать графемные кластеры, а не отдельные UTF-16 единицы JavaScript; смещения ProseMirror и сервиса проверки текста переводить явно. Проверить ввод и операции удаления/замены на границе символов с Bluetooth-клавиатуры на Android. Базовая проверка предоставленных файлов запускается `python tests/check_docx_unicode.py`; после появления импорта/экспорта добавить сквозной тест с сохранением.

## Vim-команды первой версии

Режимы: **Normal, Insert, Visual**. В строке состояния показывать активный режим. На Windows и Android вводить Vim-команды с физической клавиатуры; на Android предполагается Bluetooth-клавиатура. В Insert обычный ввод текста имеет приоритет над Vim-командами.

| Группа | Команды MVP |
| --- | --- |
| Переключение режима | `i`, `a`, `o`, `Esc`, `v` |
| Перемещение | `h`, `j`, `k`, `l`, `w`, `b`, `e`, `0`, `$`, `gg`, `G` |
| Редактирование | `x`, `dd`, `yy`, `p`, `u` |
| Поиск | `/` и переход к следующему совпадению `n` |
| Повтор | Числовой префикс для движений и простых операций, например `3w`, `2dd` |

В первой версии реализуется перечисленный набор, с тем же синтаксисом команд и поведением режимов, что в Vim. **Целевое требование к готовому приложению — полноценный ввод Vim-команд с клавиатуры на обеих платформах**, включая расширение набора после MVP. Макросы, регистры, текстовые объекты и `:ex`-команды вынесены в следующие этапы и должны быть отдельно спроектированы; не объявлять приложение полностью совместимым с Vim до их реализации и проверки. Для `j/k` необходимо явно проверить визуальные строки после переноса текста, особенно в мобильном виде.

### Русская и английская раскладки для Vim

**Обязательное требование:** все реализованные Vim-команды одинаково срабатывают при выбранной русской и английской раскладке клавиатуры как на Windows, так и на Bluetooth-клавиатуре Android. На физической клавиатуре ориентироваться на положение клавиши (`KeyboardEvent.code`), а не только на введённый символ (`key`). Например, движения `h/j/k/l` должны работать на тех же клавишах при символах `р/о/л/д`; `i/a/o/v/x/u` — при `ш/ф/щ/м/ч/г`; `dd`, `yy`, `gg` — при `вв`, `нн`, `пп`. Числовые префиксы и `Esc` работают в обеих раскладках. Для `/` учитывать клавишу `Slash`.

В **Insert** никакой перевод раскладки не применять: кириллица вводится и редактируется как обычный текст. Игнорировать командные события во время IME composition (`isComposing`). Если Android WebView для Bluetooth-клавиатуры передаёт ненадёжный `code`, использовать проверенный запасной путь по `key` с таблицей соответствий русской QWERTY-раскладки. Проверять не только одиночные клавиши, но и последовательности `dd`, `gg`, `3w` и поиск при смене раскладки между нажатиями. Экранные кнопки-заменители Vim-команд в объём не входят.

## Представление и платформы

- На Windows и Android по умолчанию открывается **крупный поточный текст**, близкий по удобству чтения к мобильному виду Microsoft Word: без уменьшения страницы A4 под экран, с комфортным размером шрифта (ориентир 19 px), нормальным межстрочным интервалом и полями для чтения. Минималистичный интерфейс вторичен по отношению к тексту.
- Windows: компактная панель форматирования, поддержка мыши и клавиатуры; вид страницы доступен переключателем.
- Android: поточный текст по ширине экрана и полное управление редактором с Bluetooth-клавиатуры. Сенсорный интерфейс остаётся доступным для системных диалогов и переключения вида, но не заменяет Vim-клавиши. Вид страницы доступен переключателем.
- Переключение вида не меняет документ и позицию курсора. Проверить на длинных абзацах и таблицах.
- На Windows и Android добавить кнопку навигации по заголовкам. Она открывает список заголовков документа; выбор пункта перемещает курсор к выбранному заголовку и закрывает меню. На телефоне список должен быть компактным, как в мобильном Word, и не уменьшать текст документа постоянно.
- Несколько документов открываются одновременно в отдельных окнах приложения на Windows и Android. На Android каждый файл должен иметь отдельную карточку в системном списке последних приложений, как у Google Docs; на совместимых планшетах окна могут располагаться рядом. Для устройств без поддержки нужного режима предусмотреть список открытых документов внутри приложения. Каждый документ независимо хранит позицию курсора, выбранный вид и состояние сохранения. Повторное открытие уже открытого файла переводит к его окну.
- Запускать приложение в отдельном стартовом окне со списком черновиков и ранее открытых файлов, а также кнопками «Открыть» и «Новый документ». После выбора открывать редактор в окне документа; закрытие последнего окна документа возвращает к стартовому экрану.
- Оконные команды Vim переосмыслить для внешних окон: `Ctrl-W s/v` и `:split`/`:vsplit` открывают второе окно того же документа без деления экрана; `Ctrl-W w/W/p/h/j/k/l` переключают открытые окна. Два окна одного файла разделяют текст и автосохранение, но сохраняют собственные курсор и прокрутку. На Android-телефоне `h/k` переключают к предыдущему окну, `j/l` — к следующему. Подробная таблица команд и ограничения Android — в `roadmap.md`.
- Работа с файлами через системный выбор документа и сохранение, включая доступные облачные расположения. Автосохранение рабочего состояния не заменяет сохранение `.docx`.

## Автосохранение и облачные файлы

- После изменений автоматически сохранять локальное рабочее состояние каждого документа по его постоянному ID с задержкой после набора; восстанавливать все открытые документы после закрытия или сбоя. Показывать время последнего успешного автосохранения и наличие несохранённых изменений в DOCX. Не использовать один общий черновик `current.json` для всех окон.
- Для документа с выбранным местом сохранения автоматически обновлять DOCX без потери исходника: записывать безопасно и оставлять восстановимую локальную копию. Период и поведение автоматической записи должны настраиваться; сообщения об ошибках в интерфейсе не показывать.
- Поддержать сохранение и открытие в **OneDrive и Яндекс Диске** на Windows и Android. При проектировании проверить два пути: системный выбор файла/документ-провайдер облачного приложения и прямое подключение аккаунта через официальный API. Выбрать работающий путь отдельно для каждого сервиса и платформы; наличие установленного облачного приложения не должно молча считаться гарантией поддержки.
- Сетевая синхронизация не должна блокировать набор текста. При отсутствии сети сохранять локальную версию и показывать очередь синхронизации. При конфликте изменений между устройствами сохранять обе версии и предлагать пользователю выбрать, какую оставить; не перезаписывать удалённую версию молча.
- Учётные данные облака хранить в защищённом хранилище платформы. Не помещать токены и содержимое документов в журналы. Первое подключение облака требует явного действия пользователя.
- До реализации облачной части проверить вход, открытие, обновление, офлайн-правки, повторную синхронизацию и конфликт отдельно на Windows и Android для OneDrive и Яндекс Диска.

## Набор документов для приёмки

Пользователь предоставил шесть файлов в `e/`. Их содержимое не копировать в документацию или публичный репозиторий. По структуре DOCX:

| Файл | Что проверять | Наблюдаемое покрытие |
| --- | --- | --- |
| `Документ (2).docx` | Минимальный импорт и кириллица | 2 абзаца, короткий текст. |
| `Документ.docx` | Кириллица в одном абзаце | 1 абзац. |
| `заметки -- коренина.docx` | Абзацы, табуляция, длинные русские строки | 31 абзац, 1 табуляция. |
| `заметки.docx` | Короткий документ | 2 абзаца. |
| `квест1.docx` | Длинный текст, курсор, прокрутка и разрыв страницы | 50 абзацев, около 2900 слов, 1 явный разрыв страницы. |
| `Толстой.docx` | Длинный русский текст, курсив и ручные переносы | 63 абзаца, около 2400 слов, 3 курсивных фрагмента. |

Недостающее покрытие: заголовки со стилями, жирный/подчёркнутый текст, списки, таблицы, изображения, ссылки, колонтитулы, сноски, комментарии и исправления. Для этого потребуются дополнительные обезличенные документы, созданные в Word/LibreOffice. Синтетические файлы для автоматических тестов полезны, но не заменяют проверку на реальных документах. Происхождение предоставленных файлов не определялось.

## Критерии готовности первой версии

1. Приложение запускается на Windows и Android, открывает DOCX через системный диалог и сохраняет новый DOCX, который открывается в Word или LibreOffice.
2. Для шести файлов из `e/` русский текст и элементы из поддерживаемого списка сохраняются после цикла «открыть → изменить → сохранить → открыть»; потери фиксируются по элементам, а не только по внешнему виду. Отдельно проверяются добавленные документы со списками, таблицами и изображениями.
3. Исходный файл с неподдерживаемыми элементами остаётся целым: первое сохранение предлагает новый путь, сообщения об ошибках и предупреждения не выводятся.
4. Переключение «Страница / Мобильный вид» сохраняет текст, форматирование и разумную позицию курсора.
   Мобильный вид выбран по умолчанию на обеих платформах; на телефоне текст остаётся крупным и читаемым без горизонтальной прокрутки.
5. Команды из таблицы Vim работают одинаково на физических русской и английской раскладках Windows и Bluetooth-клавиатуре Android, с кириллицей в документе и переносами строк. Проверить смену раскладки посреди команды и обычный ввод русского текста в Insert.
6. Орфографические замечания для русского и английского можно открыть, заменить или проигнорировать. Сетевая грамматика работает только после явного включения.
7. После аварийного закрытия восстанавливается последнее локальное рабочее состояние; сохранённый DOCX не повреждается.
8. Автосохранение показывает своё состояние и не теряет изменения при сбое или временном отсутствии сети.
9. На Windows и Android можно открыть и сохранить DOCX в OneDrive и Яндекс Диске; при конфликте версий исходные данные обеих сторон сохраняются.
10. На Windows и Android одновременно открываются как минимум два DOCX в отдельных окнах/Activity; правки, курсор, автосохранение и сохранение одного документа не меняют другой. Проверить переход между ними и восстановление обоих после перезапуска.

## Решения, которые можно уточнить позднее

- Если требуется точное сохранение сложных Word-документов, нужно пересмотреть конвертер до реализации этапа 4.
- Если грамматика обязана работать офлайн на Android, потребуется отдельное исследование локального движка и размера приложения.
- Для полной совместимости с Vim после MVP составить отдельную матрицу команд, операторов, регистров, макросов и `:ex`-команд; проверить их на Windows и Bluetooth-клавиатуре Android в обеих раскладках.
