# Проверка сохранения без изменений

24.10.2026. Сохранение привязано к содержимому модели документа, а не к фокусу окна, положению курсора или времени последнего обращения. SHA-256 считается от JSON документа Tiptap: учитываются текст и форматирование. Для локального файла хранится хэш последней **успешно записанной** модели и путь; для облака — хэш последней **успешно загруженной** модели и версия источника. Неуспешная запись не продвигает эти отметки.

При передаче права редактирования старое окно публикует изменения и завершает сохранение. Новое окно ещё раз читает общий снимок сессии, загружает его в редактор и только затем разрешает ввод. Если Android передал право до подтверждения старого окна, редактор остаётся недоступным до подтверждения. Повторный вызов сохранения сравнивает актуальный снимок с подтверждённым содержимым и не экспортирует DOCX без изменений. Изменение курсора, прокрутка и переключение окон не создают новую версию черновика. Изменение вида документа может обновить только метаданные черновика.

Проверены сценарии: неизменный документ, перемещение курсора, правка текста, изменение форматирования, отмена правки до последней сохранённой версии, неудачная запись, новый путь сохранения и ожидание облачной записи. Если правку отменили, пока старый облачный снимок ещё в очереди, он удаляется; если отправка уже выполняется, новая версия ставится в очередь следом. Локальный источник перед записью сверяется по версии файла; при внешнем изменении исходник не перезаписывается, правки сохраняются отдельным черновиком. Удалённая запись использует проверку версии API.

Исследованы типовые риски сохранения на Android: [жизненный цикл Activity](https://developer.android.com/guide/components/activities/activity-lifecycle) и [завершение процесса системой](https://developer.android.com/guide/components/activities/process-lifecycle). Сохранение выполняется во время работы после паузы набора, при скрытии окна и перед обычным закрытием; данные записываются в черновик до DOCX. Однако принудительное завершение процесса сразу после ввода и до завершения записи на диск нельзя полностью исключить при сохранении с задержкой. Это ограничение не связано с переключением окон и требует отдельного долговременного нативного журнала правок для строгой гарантии при аварийном завершении.
