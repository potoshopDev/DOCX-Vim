# Этап 8: облачные копии OneDrive и Яндекс Диска

## Как выбирается основной файл

Основной файл — тот, который пользователь открыл. «Открыть DOCX» перечитывает выбранный локальный файл и обновляет его черновик, не обращаясь к облаку. Выбор документа в списке «Яндекс Диск» скачивает выбранный удалённый файл и обновляет его черновик, не обращаясь к локальной копии. Редактор подписывает источник: «Локальный», «Яндекс Диск» или «Черновик». Черновики скрыты за отдельной кнопкой на стартовом экране. Открытие резервного черновика создаёт самостоятельную копию без привязки к исходному файлу.

После авторизации список Яндекс Диска показывает DOCX из всех папок. Открытый облачный файл появляется в недавних, и последующие правки отправляются в тот же путь. Повторное открытие перечитывает удалённую версию. Если источник недоступен, приложение предлагает открыть черновик отдельно; оно не подменяет источник молча.

Кнопка **«Яндекс Диск»** есть на стартовом экране и в меню редактора. Она открывает отдельный список DOCX на Диске; из редактора приложение возвращается к стартовому экрану с раскрытым списком. В редакторе нижняя надпись **«✓ Облако»** или **«✕ Локальный»** показывает источник текущего файла и не открывает меню. Для документа без выбранного файла отображается **«✕ Черновик»**. Черновик облачного файла обновляется в фоне, а его DOCX отправляется в исходный путь на Яндекс Диске.

Один документ может иметь две независимые облачные копии. Сначала приложение сохраняет локальный черновик и резервный DOCX, затем отправляет копии через отдельные очереди. Ошибка одного сервиса не останавливает другой. На Windows используются синхронизируемые папки; на Android — прямые API сервисов, поскольку мобильные клиенты не обязаны синхронизировать локальные папки.

## Windows

1. Подключить Яндекс Диск в настройках стартового окна.
2. Нажать **«Яндекс Диск»** на стартовом экране или в меню редактора и выбрать DOCX. Список показывает только поддерживаемый формат `.docx`.
3. Редактировать файл. Черновик сохраняется локально, а изменённый DOCX отправляется в выбранный облачный путь. Проверить результат в Яндекс Диске.

Ранее привязанные копии в синхронизируемых папках продолжают обрабатываться очередью сохранения. Добавление новой независимой копии OneDrive и Яндекса через интерфейс редактора требует отдельного переработанного управления: прежняя панель «Облака» удалена по новому требованию.

## Android: регистрация приложений OAuth

Для прямого доступа нужен публичный Client ID OAuth-приложения. Для Яндекс Диска в сборку уже включён Client ID приложения DOCX Vim: пользователю достаточно нажать «Подключить». Для OneDrive пока нужно зарегистрировать приложение Microsoft и ввести его Client ID. Секреты приложения в мобильную сборку не добавлять.

1. [Microsoft Entra App registrations](https://entra.microsoft.com/) → создать приложение с поддержкой личных аккаунтов Microsoft. Добавить делегированное разрешение Microsoft Graph `Files.ReadWrite`, разрешить **public client flows** (device code flow). Скопировать **Application (client) ID**. Вход выполняется через официальный экран Microsoft и код устройства; приложение запрашивает `offline_access Files.ReadWrite`.
2. Для использования другого приложения Яндекса: [Яндекс OAuth](https://oauth.yandex.ru/client/new) → создать приложение **«Для авторизации пользователей»**. Указать Redirect URI `https://oauth.yandex.ru/verification_code`, выдать разрешения Яндекс Диска на чтение и запись (`cloud_api:disk.read`, `cloud_api:disk.write`). Скопировать Client ID в раскрывающийся пункт «Другой Client ID Яндекс OAuth». Вход выполняется в браузере с PKCE; выданный код нужно вернуть в DOCX Vim.

Параметры протоколов описаны в [Microsoft device code flow](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code) и [Яндекс OAuth с выводом кода](https://yandex.com/dev/id/doc/en/codes/screen-code).

## Android: подключение копий

1. Открыть стартовое окно DOCX Vim → **Настройки**. Ввести Client ID Microsoft для OneDrive; для Яндекс Диска идентификатор уже включён в сборку.
2. Нажать **Подключить** для OneDrive. В браузере открыть адрес Microsoft, показанный приложением, и ввести код. Дождаться надписи «OneDrive подключён».
3. Нажать **Подключить** для Яндекс Диска. Разрешить доступ в браузере, скопировать показанный код в поле DOCX Vim и нажать **Продолжить**.
4. Нажать **«Яндекс Диск»**, выбрать DOCX в списке и редактировать его. Исходный файл обновляется в облаке; резервный черновик остаётся на устройстве. Ранее привязанные облачные копии продолжают отправляться автоматически. Создание новых копий в обоих сервисах одновременно остаётся отдельной задачей интерфейса.

Отключение аккаунта в настройках удаляет токен устройства. OAuth-токены хранятся в системном хранилище ключей (Android Keystore / Windows Credential Manager); в черновиках остаются только идентификаторы целевых файлов и состояние синхронизации. Client ID хранится в настройках как несекретный параметр.

## Повторы и конфликты

- Отправка идёт в фоне, а при сетевой ошибке очередь повторяется с увеличивающейся паузой до пяти минут. При запуске документа актуальная версия снова ставится в очередь. Приложение должно быть запущено для отправки; системная фоновая задача при закрытом приложении пока не реализована.
- Перед повторной записью OneDrive сверяется `eTag`, Яндекс Диск — `md5` или время изменения. При внешнем изменении вместо перезаписи создаётся локальный файл конфликта в `AppData/cloud-conflicts/`. В меню редактора появится кнопка **«Сохранить конфликтную копию»**. Для первой загрузки существующий удалённый файл также считается конфликтом.
- На Windows перед перезаписью локальной синхронизируемой копии сравнивается SHA-256 с предыдущей записью.
- При истечении авторизации или отзыве доступа очередь ждёт повтора. Если вход не возобновился автоматически, нужно заново подключить аккаунт в настройках.
- При размере DOCX более 250 МБ текущая прямая загрузка OneDrive требует расширения до upload session.

## Проверка

Типизация и сборки Windows/Android проверяются локально. Реальная авторизация и передача в аккаунты требуют проверки на телефоне с зарегистрированными OAuth-приложениями. Нужно проверить оба сервиса, повтор после отключения сети, перезапуск, истечение токена и изменение облачной копии извне.
