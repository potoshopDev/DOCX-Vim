# Этап 8: облачные копии через системные файлы

Приложение сохраняет до двух копий одного DOCX: одну в выбранный файл OneDrive, другую — в выбранный файл Яндекс Диска. Привязки хранятся у документа, а не в общих настройках. Доступ к облаку предоставляет установленный системный клиент или Android DocumentsProvider; пароли и OAuth-токены DOCX Vim не запрашивает и не хранит.

## Подключение на Windows

1. Установить и авторизовать официальные клиенты [OneDrive](https://support.microsoft.com/en-us/onedrive/store-your-work-files-on-onedrive) и [Яндекс Диска](https://yandex.com/support/yandex-360/customers/disk/desktop/windows/en/installation).
2. Убедиться, что в Проводнике доступны синхронизируемые папки обоих клиентов. Для Яндекс Диска нужную папку при необходимости отметить «Сохранить на компьютере».
3. В DOCX Vim открыть документ, нажать **«Облака»** в нижней панели, затем **«Выбрать файл»** у OneDrive. В системном диалоге выбрать папку OneDrive и имя `.docx`.
4. Повторить для Яндекс Диска. При следующих правках приложение обновляет оба выбранных файла в фоне; состояние каждой записи видно в панели «Облака».
5. Проверить значок синхронизации клиента и наличие файла в веб-интерфейсе каждого сервиса. Надпись «Файл передан провайдеру» означает успешную запись в выбранный системный файл, а не подтверждение выгрузки на сервер.

## Подключение на Android

1. Установить OneDrive и Яндекс Диск, войти в нужные аккаунты.
2. В документе DOCX Vim открыть **«Облака»** и **«Выбрать файл»** нужного сервиса. В системном выборе файлов открыть соответствующее расположение, если оно предлагается, и создать `.docx`.
3. Повторить для второго сервиса. Затем изменить документ и проверить файлы непосредственно в приложениях OneDrive и Яндекс Диск.

Android показывает в системном диалоге лишь те облачные расположения, которые предоставляют установленный DocumentsProvider и разрешают создание/запись документов. Наличие установленного приложения само по себе этого не гарантирует. Особенно важно проверить Яндекс Диск на реальном устройстве: его справка предупреждает, что изменения скачанного файла могут не синхронизироваться автоматически. Если сервис не появляется в диалоге либо не загружает изменённый файл, такая привязка через системный выбор пока недоступна; для неё потребуется прямое подключение по API.

## Очереди и защита документа

- Локальный черновик и резервный DOCX записываются до попытки записи облачных копий. Каждая облачная привязка имеет собственную очередь, состояние и повтор через 5–300 секунд. Сбой одного расположения не останавливает другое.
- При повторном открытии документа приложение восстанавливает черновик и снова передаёт актуальную версию выбранным провайдерам. Ожидание возможно, пока выбранный файл недоступен.
- Перед обновлением уже записанного файла приложение сравнивает его SHA-256 с последней записанной версией. Если файл изменился вне DOCX Vim, приложение не перезаписывает его и сохраняет свою актуальную копию в `AppData/cloud-conflicts/<ID>-<provider>.docx`. В панели показывается конфликт и кнопка «Сохранить копию», доступная также на Android. Чтобы решить конфликт, открыть обе версии, выбрать нужное содержание и заново выбрать целевой файл.
- Состояние «Файл передан провайдеру» не гарантирует, что облачный клиент уже закончил синхронизацию. На Android фактическую выгрузку и офлайн-поведение нужно подтвердить на конкретных версиях провайдеров.

## Что проверить на реальных устройствах

Сборки `npm run build`, Windows `tauri build --debug --no-bundle` и Android ARM64 `tauri android build --debug --target aarch64 --apk --ci` проходят. Реальные облачные аккаунты и провайдеры в этой проверке не подключались.

- Windows: выбор двух папок, автосохранение в обе, недоступность одной папки, восстановление после перезапуска, внешнее изменение файла и локальная копия конфликта.
- Android: присутствие обоих провайдеров в системном диалоге, создание DOCX и повторная запись по выданному URI, доступ после перезапуска, реальная синхронизация в оба аккаунта, поведение без сети.
- Если Android-провайдер Яндекс Диска не поддерживает нужную операцию, завершить этап прямым API Яндекс Диска с OAuth PKCE и защищённым хранением токена. Аналогично для OneDrive, если его провайдер не обеспечивает повторную запись.
