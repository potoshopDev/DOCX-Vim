# Этап 8: облачные копии OneDrive и Яндекс Диска

Один документ может иметь две независимые облачные копии. Сначала приложение сохраняет локальный черновик и резервный DOCX, затем отправляет копии через отдельные очереди. Ошибка одного сервиса не останавливает другой. На Windows используются синхронизируемые папки; на Android — прямые API сервисов, поскольку мобильные клиенты не обязаны синхронизировать локальные папки.

## Windows

1. Установить и настроить официальные клиенты OneDrive и Яндекс Диска. Проверить папки синхронизации в Проводнике.
2. В DOCX Vim открыть документ → **Облака** → **Выбрать файл** у OneDrive; выбрать `.docx` в папке OneDrive.
3. Повторить для Яндекс Диска. После правок обе копии обновляются в фоне.
4. Проверить выгрузку в приложении или веб-интерфейсе каждого сервиса. «Файл передан провайдеру» означает успешную запись в локальный файл, а не завершение серверной синхронизации.

## Android: регистрация приложений OAuth

Для прямого доступа необходимы **Client ID** двух собственных OAuth-приложений. Это публичные идентификаторы, их можно вводить в настройках DOCX Vim; секрет приложения в мобильную сборку не добавлять. Регистрацию можно выполнить в браузере на ПК, а Client ID перенести на телефон.

1. [Microsoft Entra App registrations](https://entra.microsoft.com/) → создать приложение с поддержкой личных аккаунтов Microsoft. Добавить делегированное разрешение Microsoft Graph `Files.ReadWrite`, разрешить **public client flows** (device code flow). Скопировать **Application (client) ID**. Вход выполняется через официальный экран Microsoft и код устройства; приложение запрашивает `offline_access Files.ReadWrite`.
2. [Яндекс OAuth](https://oauth.yandex.ru/client/new) → создать приложение **«Для авторизации пользователей»**. Указать Redirect URI `https://oauth.yandex.com/verification_code`, выдать разрешения Яндекс Диска на чтение и запись (`cloud_api:disk.read`, `cloud_api:disk.write`). Скопировать Client ID. Вход выполняется в браузере с PKCE; выданный код нужно вернуть в DOCX Vim.

Параметры протоколов описаны в [Microsoft device code flow](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code) и [Яндекс OAuth с выводом кода](https://yandex.com/dev/id/doc/en/codes/screen-code).

## Android: подключение копий

1. Открыть стартовое окно DOCX Vim → **Настройки**. Ввести Client ID Microsoft и Яндекса.
2. Нажать **Подключить** для OneDrive. В браузере открыть адрес Microsoft, показанный приложением, и ввести код. Дождаться надписи «OneDrive подключён».
3. Нажать **Подключить** для Яндекс Диска. Разрешить доступ в браузере, скопировать показанный код в поле DOCX Vim и нажать **Продолжить**.
4. Открыть документ → **Облака** → **Подключить копию** для каждого сервиса. В корне каждого аккаунта появится файл вида `DOCX Vim - Название - ID.docx`. После каждой правки обе копии отправляются автоматически. Статус **«Сохранено в облаке»** означает успешный ответ API сервиса.

Отключение аккаунта в настройках удаляет токен устройства. Отключение копии в документе останавливает отправку этого документа и не удаляет загруженный DOCX. OAuth-токены хранятся в системном хранилище ключей (Android Keystore / Windows Credential Manager); в черновиках остаются только идентификаторы целевых файлов и состояние синхронизации. Client ID хранится в настройках как несекретный параметр.

## Повторы и конфликты

- Отправка идёт в фоне, а при сетевой ошибке очередь повторяется с увеличивающейся паузой до пяти минут. При запуске документа актуальная версия снова ставится в очередь. Приложение должно быть запущено для отправки; системная фоновая задача при закрытом приложении пока не реализована.
- Перед повторной записью OneDrive сверяется `eTag`, Яндекс Диск — `md5` или время изменения. При внешнем изменении вместо перезаписи создаётся локальный файл конфликта в `AppData/cloud-conflicts/`. Его можно сохранить через кнопку **«Сохранить копию»** и сравнить с версией в облаке. Для первой загрузки существующий удалённый файл также считается конфликтом.
- На Windows перед перезаписью локальной синхронизируемой копии сравнивается SHA-256 с предыдущей записью.
- При истечении авторизации или отзыве доступа очередь ждёт повтора. Если вход не возобновился автоматически, нужно заново подключить аккаунт в настройках.
- При размере DOCX более 250 МБ текущая прямая загрузка OneDrive требует расширения до upload session.

## Проверка

Типизация и сборки Windows/Android проверяются локально. Реальная авторизация и передача в аккаунты требуют проверки на телефоне с зарегистрированными OAuth-приложениями. Нужно проверить оба сервиса, повтор после отключения сети, перезапуск, истечение токена и изменение облачной копии извне.
