Порядок обновлён: фоновое автосохранение включено в этап DOCX, потому что до облака нужна восстановимая локальная версия. Сборка ARM64 установлена и запущена на телефоне; подключение и проверка физической Bluetooth-клавиатуры ещё предстоят.

Для этапа 3 сохранён [снимок Android-эмулятора](android-editor-final.png). Крупный поточный вид выбран по умолчанию на обеих платформах. Установка и запуск на реальном телефоне подтверждены пользователем; работу с Bluetooth-клавиатурой ещё предстоит проверить.

Итог этапа 4: добавлены импорт через Mammoth с очисткой HTML, отдельные черновики по ID, фоновый экспорт DOCX через Web Worker, последовательная запись в выбранный файл и локальная резервная копия DOCX. На Android-эмуляторе системный выбор открыл русский DOCX, сохранение через document provider создало новый файл, изменение текста обновило DOCX автоматически, а черновик и доступ к файлу сохранились после перезапуска. Выгруженный DOCX проверен как ZIP и содержит кириллицу. На Windows пользователь подтвердил открытие и сохранение через системные диалоги; после правки выбранный DOCX, черновик и резервная копия обновились без повторной команды сохранения. Несколько окон относятся к этапу 5.

Фоновое автосохранение этапа 4: после паузы ввода сохранять локальный черновик; после выбора места сохранения обновлять DOCX автоматически в отдельной очереди, не блокируя ввод и прокрутку. Повторные правки во время записи не должны теряться: сохранять версии по порядку или заменять ожидающую запись более новой. При ошибке оставлять черновик и повторять запись позднее. Ручное «Сохранить» должно записывать последнюю версию документа. Проверить это на длинном файле и при закрытии приложения во время сохранения.

Стартовое окно этапа 5 не является редактором. Оно показывает черновики и историю открытых файлов отдельно: история хранит ссылку на файл и его внутренний ID, черновик хранит восстановимое содержание. Если источник более недоступен, черновик остаётся доступен. Кнопки «Открыть» и «Новый документ», а также вход во все настройки приложения размещаются в стартовом окне. В настройках задаются параметры автосохранения, языка проверки, раскладки Vim, вида документа по умолчанию и скрытия верхнего меню редактора; переключатель Vim-управления появляется на этапе 6, переключатели автозамены и автодополнения и управление пользовательским словарём — на этапе 7, подключения облачных сервисов — на этапе 8. Скрытое меню не занимает место над текстом; вернуть его можно через настройки стартового окна. Настройка сохраняется между запусками и действует на Windows и Android. Окно редактора оставляет только инструменты работы с текущим документом. При закрытии последнего окна документа пользователь возвращается на стартовый экран.

На этапе 6 отключение Vim-управления возвращает обычный ввод и редактирование текста: буквенные клавиши не вызывают команды Normal/Visual, стандартные сочетания редактирования работают как обычно. Переключение не меняет содержимое документа и сохраняется между запусками. При повторном включении Vim редактор начинает в режиме Normal.

Помощь при наборе в этапе 7 работает на Windows и Android с физической или Bluetooth-клавиатурой. Автозамена во время ввода преобразует заданные последовательности, например `--` в длинное тире и парные прямые кавычки в русские «ёлочки» с учётом контекста. Замены настраиваются и откатываются обычным `Undo` как одно действие. Автодополнение после короткой паузы показывает ненавязчивую подсказку ближайшего слова из словаря выбранного языка. `Ctrl+N` и `Ctrl+P` выводят варианты исправления слова у курсора; если список уже открыт, выбирают следующий и предыдущий вариант соответственно. `Tab` вставляет выбранный вариант, `Esc` скрывает подсказку. Сочетание `Ctrl+Space` нельзя считать обязательным на Android: оно переключает язык ввода на проверенном телефоне. На Windows его можно оставить для вызова или принятия подсказки. Фоновый поиск не задерживает ввод и отбрасывает устаревшие результаты после изменения текста или положения курсора. При включённом Vim автозамена и автодополнение действуют только в режиме Insert и не перехватывают команды Normal/Visual; при выключенном Vim они работают во время обычного ввода. Подсказка не меняет текст без явного принятия (кроме настроенных правил автозамены). Проверить русскую и английскую раскладки, границы слов и поведение курсора после замены. По результатам проверки на Android исправить обработку `Tab`: сейчас подсказка появляется или обновляется только после касания экрана; она должна работать с одной Bluetooth-клавиатуры без потери фокуса редактора.

Для слова, отмеченного как неизвестное, предусмотреть действие «Добавить в словарь». Слово сохраняется в локальном пользовательском словаре соответствующего языка, больше не подсвечивается как орфографическая ошибка и учитывается при автодополнении. Словарь сохраняется между запусками и доступен во всех документах на устройстве. В настройках стартового окна можно просмотреть и удалить добавленные слова.

На этапе 8 один документ может иметь две облачные привязки одновременно — OneDrive и Яндекс Диск. У каждой привязки собственные версия, состояние очереди и повторные попытки; сбой одного сервиса не останавливает сохранение в другой и не затрагивает локальный черновик.

Для нескольких файлов каждый документ получает постоянный внутренний ID и отдельный черновик. Окно хранит только ID активного документа; путь исходного файла, путь сохранения, состояние DOCX и позиция курсора привязаны к документу, а не к глобальному `current.json`. При открытии одного файла повторно следует переводить к существующему окну, чтобы не получить конкурирующие записи.

По [документации Tauri](https://v2.tauri.app/learn/mobile-multiwindow/) дополнительные Android-окна создают отдельные Activity, но на телефоне обычно попадают в один стек «Назад». Для поведения как у Google Docs с отдельными карточками документов в системном списке последних приложений нужен Android document-centric task (см. [Android Recents](https://developer.android.com/guide/components/activities/recents)); это отдельная нативная интеграция сверх Tauri WebviewWindow. Текущий `AndroidManifest.xml` использует `singleTask`: перед этапом 5 пересмотреть launchMode и запуск с `FLAG_ACTIVITY_NEW_DOCUMENT`, проверить повторное открытие, разрешения URI, восстановление после выгрузки процесса и ограничения версий Android. Tauri multi-window заявлен для Android 12L/API 32+; ниже нужна проверенная запасная навигация по открытым документам внутри приложения.

### Оконные команды Vim без разделения редактора

Комбинации из [справки Vim по окнам](https://vimhelp.org/windows.txt.html) получают единое значение на Windows и Android:

| Команда | Поведение приложения |
| --- | --- |
| `Ctrl-W s`, `Ctrl-W v`, `:split`, `:vsplit` | Открыть отдельное окно того же документа; вертикальная/горизонтальная ориентация не задаётся. Каждое окно имеет собственный курсор и прокрутку, текст и автосохранение общие. |
| `Ctrl-W n`, `:new`, `:vnew` | Открыть отдельное окно нового пустого документа. `:split {file}` и `:vsplit {file}` открывают указанный файл в отдельном окне. |
| `Ctrl-W w` / `Ctrl-W W` | Следующее / предыдущее окно в устойчивом порядке открытия; поддержать числовой префикс для выбора окна. |
| `Ctrl-W p` | Вернуться к предыдущему активному окну. |
| `Ctrl-W h/j/k/l` | На Windows переход к ближайшему окну по его положению; если однозначного соседа нет, переход в порядке окон. На телефоне `h/k` — предыдущее, `j/l` — следующее, так как пространственного расположения нет. |
| `Ctrl-W c`, `:close` | Закрыть текущее окно после сохранения черновика; если это последнее окно документа, сам документ остаётся доступен через список черновиков. |

Размеры, поворот, обмен местами и `Ctrl-W o` не имеют прямого аналога для отдельных Android tasks. Их поведение определять отдельно; `Ctrl-W o` не должен закрывать другие документы и терять несохранённые изменения. Оконный диспетчер работает по ID окон и документов; два окна одного DOCX обязаны обмениваться изменениями через одну общую модель, иначе возникнут конфликты записи. На Android для команд перехода между отдельными карточками понадобится нативная интеграция с `ActivityManager.getAppTasks()` и `AppTask.moveToFront()`; один только `WebviewWindow.setFocus()` не подтверждает переключение между tasks. Команды проверять на физической и Bluetooth-клавиатуре в русской и английской раскладке.
