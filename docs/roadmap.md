Для этапа 3 сохранён [снимок Android-эмулятора](android-editor-final.png). Крупный поточный вид выбран по умолчанию на обеих платформах; реальное устройство и Bluetooth-клавиатура ещё не проверялись.

Текущий прогресс этапа 4: добавлены импорт через Mammoth с очисткой HTML и предупреждениями о неподдерживаемых элементах, ручной экспорт DOCX, отдельные черновики по ID и восстановление после перезапуска. В браузере проверены импорт русского файла, экспорт с сохранением кириллицы и восстановление черновика. Системные диалоги Tauri, запись через Android document provider и поведение нескольких окон на устройстве ещё требуют испытаний; поэтому этап не отмечен завершённым.

Для нескольких файлов каждый документ получает постоянный внутренний ID и отдельный черновик. Окно хранит только ID активного документа; путь исходного файла, путь сохранения, состояние DOCX и позиция курсора привязаны к документу, а не к глобальному `current.json`. При открытии одного файла повторно следует переводить к существующему окну, чтобы не получить конкурирующие записи.

По [документации Tauri](https://v2.tauri.app/learn/mobile-multiwindow/) дополнительные Android-окна создают отдельные Activity, но на телефоне обычно попадают в один стек «Назад». Для поведения как у Google Docs с отдельными карточками документов в системном списке последних приложений нужен Android document-centric task (см. [Android Recents](https://developer.android.com/guide/components/activities/recents)); это отдельная нативная интеграция сверх Tauri WebviewWindow. Текущий `AndroidManifest.xml` использует `singleTask`: перед этапом 5 пересмотреть launchMode и запуск с `FLAG_ACTIVITY_NEW_DOCUMENT`, проверить повторное открытие, разрешения URI, восстановление после выгрузки процесса и ограничения версий Android. Tauri multi-window заявлен для Android 12L/API 32+; ниже нужна проверенная запасная навигация по открытым документам внутри приложения.

### Оконные команды Vim без разделения редактора

Комбинации из [справки Vim по окнам](https://vimhelp.org/windows.txt.html) получают единое значение на Windows и Android:

| Команда | Поведение приложения |
| --- | --- |
| `Ctrl-W s`, `Ctrl-W v`, `:split`, `:vsplit` | Открыть отдельное окно того же документа; вертикальная/горизонтальная ориентация не задаётся. Каждое окно имеет собственный курсор и прокрутку, текст и автосохранение общие. |
| `Ctrl-W n`, `:new`, `:vnew` | Открыть отдельное окно нового пустого документа. `:split {file}` и `:vsplit {file}` открывают указанный файл в отдельном окне. |
| `Ctrl-W w` / `Ctrl-W W` | Следующее / предыдущее окно в устойчивом порядке открытия; поддержать числовой префикс для выбора окна. |
| `Ctrl-W p` | Вернуться к предыдущему активному окну. |
| `Ctrl-W h/j/k/l` | На Windows переход к ближайшему окну по его положению; если однозначного соседа нет, переход в порядке окон. На телефоне `h/k` — предыдущее, `j/l` — следующее, так как пространственного расположения нет. |
| `Ctrl-W c`, `:close` | Закрыть текущее окно после сохранения черновика; если это последнее окно документа, сам документ остаётся доступен через список черновиков. |

Размеры, поворот, обмен местами и `Ctrl-W o` не имеют прямого аналога для отдельных Android tasks. Их поведение определять отдельно; `Ctrl-W o` не должен закрывать другие документы и терять несохранённые изменения. Оконный диспетчер работает по ID окон и документов; два окна одного DOCX обязаны обмениваться изменениями через одну общую модель, иначе возникнут конфликты записи. На Android для команд перехода между отдельными карточками понадобится нативная интеграция с `ActivityManager.getAppTasks()` и `AppTask.moveToFront()`; один только `WebviewWindow.setFocus()` не подтверждает переключение между tasks. Команды проверять на физической и Bluetooth-клавиатуре в русской и английской раскладке.
