# План приложения: DOCX-редактор для Windows и Android

## Цель

Создать приложение для открытия, редактирования и сохранения `.docx`: привычное оформление документа и панель форматирования в духе Microsoft Word, адаптивный мобильный вид, управление курсором и текстом командами Vim, подсветка орфографических и грамматических ошибок с предложениями исправлений. Приоритет — работа с обычными документами без обязательного сервера.

## Рекомендуемый стек

**Tauri 2 + TypeScript/React + Tiptap (на основе ProseMirror).** Tauri собирает один интерфейс для Windows и Android. Tiptap дает модель форматированного документа, команды, клавиатурные сочетания и декорации для подсветки ошибок. Интерфейс можно сделать похожим на Word, сохраняя собственную модель документа и отдельное адаптивное представление на телефоне.

Компоненты:

- **Редактор:** Tiptap/ProseMirror, расширения для заголовков, списков, таблиц, изображений, ссылок и форматирования текста. Хранить рабочее состояние в JSON редактора; `.docx` — формат обмена и пользовательского сохранения.
- **DOCX для первой версии:** Mammoth для импорта в HTML (с последующей очисткой и преобразованием в модель редактора), `docx` для экспорта в браузерном JavaScript. Сделать явное сопоставление поддерживаемых стилей и элементов. Эта связка подходит для простых и умеренно сложных документов, но не обеспечивает точного кругового сохранения любого файла Word.
- **Vim-управление:** расширение ProseMirror с режимами Normal/Insert/Visual. Начать с `h/j/k/l`, `w/b/e`, `0/$`, `gg/G`, `i/a/o`, `Esc`, `x`, `dd`, `yy`, `p`, `u`, `/` и повторов команд; затем расширять до полного набора Vim. Оконные команды `Ctrl-W s/v` и `:split`/`:vsplit` открывают отдельное окно того же документа вместо разделения редактора; `Ctrl-W w/W/p/h/j/k/l` переключают окна. На Android-телефоне направления `h/k` и `j/l` означают предыдущее и следующее окно. Команды должны работать одинаково с физической клавиатуры на Windows и Bluetooth-клавиатуры на Android при русской и английской раскладке. В Normal/Visual учитывать положение клавиши и запасной перевод русской раскладки; в Insert вводить кириллицу без преобразования. Экранные кнопки-заменители Vim-команд не нужны. Реализовывать движения через позиции и выделения ProseMirror, учитывая границы абзацев, таблицы, Unicode и экранные строки.
- **Проверка текста:** слой подсветки через ProseMirror decorations, список замечаний и действие «заменить/игнорировать». Для MVP использовать проверку правописания платформы там, где она доступна; грамматику подключить через настраиваемый LanguageTool сервер или лицензированный сервис. Публичный бесплатный API LanguageTool нельзя использовать для автоматических запросов приложения. Отправлять только измененные фрагменты после паузы набора, сопоставлять диапазоны с позициями документа и отменять устаревшие ответы. Язык документа и фрагмента должен быть настраиваемым, включая русский.
- **Файлы и облако:** системные диалоги открытия/сохранения Tauri; проверить работу Android с системным выбором документов, правами доступа и повторным сохранением выбранного файла. Несколько DOCX должны открываться одновременно в независимых окнах на Windows и Android; каждому документу нужны собственный ID, черновик, путь, статус сохранения, курсор и вид. На телефоне допускается переход между окнами через системный стек задач, на планшете — показ рядом, если это поддерживает устройство. Автосохранение локального рабочего состояния, автоматическая безопасная запись DOCX и явный статус сохранения. Поддержать открытие и сохранение в OneDrive и Яндекс Диске на Windows и Android, проверить системные документ-провайдеры и прямые API, офлайн-очередь, повторную синхронизацию и конфликты без потери версий.

## Представление документа

На Windows и Android по умолчанию — **крупный поточный текст без жёсткой ширины страницы**, по удобству чтения близкий к мобильному виду Microsoft Word. На телефоне не уменьшать страницу A4 до ширины экрана; ориентир размера текста — 19 px. Интерфейс обеих версий делать минималистичным и вторичным по отношению к документу. Переключатель «Страница / Мобильный вид» меняет только отображение; структура и содержание документа остаются общими. Разрывы страниц, поля, колонтитулы и точное расположение объектов Word требуют отдельного этапа. Браузерная верстка и Word могут по-разному разбивать страницы.

## Почему этот вариант проще

| Вариант | Оценка |
| --- | --- |
| Tauri + Tiptap/ProseMirror | Один код интерфейса для двух платформ; готовая модель форматированного текста и точки расширения для Vim и подсветки. Лучший старт для MVP. |
| Flutter + нативный rich-text-редактор | Хороший мобильный UI, но модель сложного документа, DOCX-конвертация и Vim-поведение потребуют больше собственной разработки. |
| CKEditor 5 + Tauri | Больше готовых возможностей Word-импорта/экспорта и пагинации, но нужные функции зависят от коммерческих/облачных сервисов; проверить цену, лицензирование и требования к сети до выбора. |
| ONLYOFFICE/LibreOffice как движок | Ближе к полной совместимости DOCX, но значительно сложнее встраивание, мобильная сборка и собственное Vim-управление. Имеет смысл лишь при обязательной высокой точности Word. |

Tiptap также предлагает коммерческую DOCX-конвертацию. По документации импорт использует сервис и доступ по подписке, а экспортный пакет выполняет конвертацию на клиенте. Если тестовые документы покажут недостаточную точность связки Mammoth + `docx`, сравнить эту опцию и CKEditor с требованиями к офлайн-работе и стоимости.

## Предлагаемые этапы

Актуальный порядок и состояние работ записаны в [docs/roadmap.md](docs/roadmap.md). Следующий этап — открытие DOCX через системный выбор файла, надёжное автосохранение каждого документа и сохранение DOCX; затем отдельные окна на Windows и Android, Vim, проверка ошибок и облачная синхронизация. Для подробных критериев первой версии см. [docs/mvp-scope.md](docs/mvp-scope.md).

После завершения каждого этапа разработки делать коммит и отправлять его в `origin/master`. Пока не создавать отдельные ветки. Перед коммитом проверять `.gitignore` и список подготовленных файлов: пользовательские DOCX из `e/`, секреты, зависимости и результаты сборки не публиковать.

## Вопросы перед реализацией

- Нужна ли полная офлайн-работа, включая грамматику? Локальный LanguageTool добавит крупную зависимость и усложнит Android; онлайн-сервис требует согласия на передачу текста.
- Насколько важна точность сложных DOCX: таблицы, изображения, сноски, колонтитулы, комментарии, отслеживание изменений? От ответа зависит выбор конвертера.
- Нужна ли только русская проверка или несколько языков? Нужны ли полноценные Vim-макросы/регистры или достаточно основных движений и операций?
